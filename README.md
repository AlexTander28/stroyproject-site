# СтройПроект — основной сайт

Публичный сайт: https://alextander28.github.io/stroyproject-site/

Текущая базовая версия: **1.0.0**, утверждённая «Северная студия». Это единственный основной репозиторий сайта. Альтернативные макеты и прототип CRM сюда не скопированы.

## Где редактировать

- `site/` — единственный источник публикуемой разметки, стилей, скриптов и ресурсов.
- `site/index.html` — основной вход.
- `site/reference-nordic.html` — совместимый перенаправляющий адрес, не вторая версия.
- `scripts/check-site.mjs` — проверка состава и ссылок ресурсов.
- `scripts/publish-pages.ps1` — проверка и выпуск только `site/` из чистой ветки `main` в служебную `gh-pages`.
- `docs/DEVELOPMENT.md` — порядок изменений, выпусков и отката.
- `docs/CRM-INTEGRATION.md` — границы будущего подключения CRM.

Для локальной работы используется checkout `production-site` внутри исходного проекта. Файлы `reference-*.html` в родительской папке — исторические макеты, не источник автопубликации. Не переносить весь родительский проект в репозиторий.

## Версии

`main` — проверенная публикуемая версия; `feature/...` и `fix/...` — работа над изменениями. Релизы помечаются тегами `v1.0.0`, `v1.0.1` и т. д. Нельзя создавать копии `site-final`, `site-new` или отдельные основные репозитории для каждого исправления.

GitHub Pages получает конкретный коммит служебной ветки `gh-pages`, а не «последнюю папку с похожим названием». Эту ветку не редактируют вручную: она создаётся из site/ командой выпуска. Версия доступна в `version.json`.

## Проверка

Требуется Node.js 24 или новее, без npm-зависимостей:

```sh
node scripts/check-site.mjs
```

Просмотр: любой статический сервер с корнем `site/`. После изменений проверить мобильный/планшетный/десктопный экран, reduced motion, форму и галерею. Проверки структуры не заменяют браузерные.

## Важные ограничения

Форма демонстрационная: не отправляет заявки и не сохраняет персональные данные. Изображения — подписанные иллюстрации, контакты/разработчик — примеры, юридические страницы — черновики. Это не готовая CRM и не утверждённые реквизиты компании.

GitHub Pages размещает статический фронтенд. Секреты, CRM, авторизация и обработка заявок должны работать на отдельном сервере, когда интеграция будет согласована. Не помещать ключи или базы клиентов в этот репозиторий либо браузерный код.

## Выпуск

После проверки и push main выполнить в PowerShell `./scripts/publish-pages.ps1`. Команда проверяет состав, чистоту checkout и совпадение main с GitHub, затем обновляет gh-pages без force push. Pages публикует эту ветку стандартным механизмом GitHub.

Текущий GitHub OAuth доступ не имеет workflow scope. Поэтому автоматический пользовательский Actions-процесс не включён; пример для будущего перехода сохранён в `docs/pages-actions.example.yml`, а не в исполняемой .github/workflows. Изменение main само по себе сайт не обновляет — нужна команда выпуска.
