# Разработка без путаницы версий

1. Открыть только `production-site` как Git checkout и обновить `main` из GitHub. При незакоммиченных изменениях сначала сохранить их; не применять destructive reset.
2. Создать ветку `fix/<задача>` или `feature/<задача>`.
3. Менять файлы в `site/`, а не исторические копии в родительской папке. Делать небольшие коммиты.
4. Пройти `node scripts/check-site.mjs` и браузерные проверки. Создать pull request; публикация из feature-ветки не выполняется.
5. Перед выпуском одинаково обновить `VERSION`, `site/version.json` и meta build-version в `site/index.html`; описать изменения в CHANGELOG.
6. После проверки объединить в `main` и выполнить `./scripts/publish-pages.ps1`. Скрипт публикует только `site/` в служебную gh-pages. Проверить статус Pages, реальную страницу, её version.json и загрузку ресурсов.
7. Пометить проверенный коммит тегом и релизом `vX.Y.Z`. Исправление — patch, новый совместимый функционал — minor, несовместимые изменения — major.

## Откат

Предпочтителен `git revert <ошибочный-коммит>` через отдельную ветку и pull request. Для восстановления конкретного релиза: отдельная ветка от текущего main, восстановить нужные site-файлы из проверенного тега, создать новый исправляющий релиз и проверить. Не переписывать историю через force push и не удалять релизные теги.

## Границы публикации

Только `site/` попадает в служебную ветку gh-pages. Она не является второй редактируемой версией и не содержит исходники CRM. Документы разработки доступны в main на GitHub, но не входят в сайт. Не публиковать рабочие логи, дампы CRM, .env, секреты, временные зависимости или весь исходный рабочий каталог.

Переход на Actions возможен после разрешения workflow scope. Готовый пример docs/pages-actions.example.yml публикует из main и проверяет pull requests; сейчас он не исполняется. Не считать автоматическую публикацию включённой до её реальной проверки.

Первый релиз — демоверсия формы. Подключение отправки требует отдельного согласования, настоящего API и end-to-end проверки; не заменять честный результат формы фиктивным сообщением об успешной отправке.
